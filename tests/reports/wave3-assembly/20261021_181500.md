## Failures
- WS receipt는 서버의 UUID v8 delivery ID를 agent parser의 v1–5 검사로 INVALID_FRAME 거부한다. ASK6312229296. HTTP receipt 성공을 WS 성공으로 계산하지 않았다.
- worker/scheduler는 migration 누락에도 ready200이다. application initialize/ready 훅 미구현, ASK6311965208. broker는503을 확인했다.
- 반복 probe 중1회 worker Client가 transaction timeout FATAL25P04를 unhandled error로 전파해 종료됐다. 지속 재현성 미확정, ASK6312338808. integration-transaction-timeout.log 보존; 해당 schema/queue는 db-inspect.mjs로 별도 정리했다. 이후 최종 probe는 완료됐다.
- CLI 권한 저장2건은 sandbox ACL 거부다. 초기 emitted CLI의 Python spawn EPERM은 공식 oracle을 별도 Python 실행하고 제공된 env seam으로 재실행했다. 91개 중89 pass/2 fail/skip0이며 실패를 생략하지 않았다.
- fixture 작성 중 timestamp offset, receipt cursor, prepare의 flat packet, SQL text/uuid join 오류를 수정했다. 이전 fixture 실패 로그와 최종 로그를 분리했다. 기능 폴더 수정0.
- Docker/Vite/npm install/lock·bash syntax·node24 image·실제 Monitor 세션 깨우기·배포 브라우저는 실행하지 않았다. Windows bootstrap 생성 성공도 호스트 검증 대상이다.
- 지정 since-compact 조회는 과거 COMPACT에서 멈춰 이후 ACK를 반영하지 못했다. 정본 스킬은 수정하지 않고 전체 issue_watch 조회도 실행했다. 최신6312338808 기준 PENDING-ACK0, `.cache/base-s4/barrier-final-full.log`.
