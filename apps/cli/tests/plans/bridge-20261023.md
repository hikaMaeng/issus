## Goal
delivery receipt→직접 ACK→fake native CLI 1회→REPORT preflight/post→application/process. ACK와 업무 종결을 분리하고 재전달·재시작·HOLD가 중복 spawn을 만들지 않는지 확인한다.

## Environment
Windows native Node/PowerShell, F:/dev/issus main. API http://127.0.0.1:18140, 기존 Postgres postgresql://issus@127.0.0.1:15440/issus. 서버·domain·runtime 편집 없음.

## Preconditions
고유 시험 저장소·별칭, bootstrap은 기존 credential provider에서 환경으로만 주입. 비밀 파일 열람/출력 없음. 실제 codex/muse 호출은 오케스트레이터만 수행. fake 자식은 시험 cwd 안의 실행 파일.

## Steps
1. npm run lint --workspace @issus/cli, npm test --workspace @issus/cli. sandbox spawn EPERM은 그대로 기록하고 runner emit + node --test --test-isolation=none을 별도로 실행한다.
2. 상태 전이·atomic journal·sid 변경 lock·effect key 불변·경로 거부·JSON prompt·정책·adapter argv·terminal 판정·snapshot refresh 단위 시험.
3. API mock 제어 시험: 재전달 10회/ACK 직후 crash/REPORT 응답 유실/mention-only/HANDOFF/HOLD·재개. spawn과 네트워크는 명시 주입하고 실제 API 시험과 구분한다.
4. apps/cli/tests/tools/runner-live.mjs: 운영 스택의 시험 저장소에 ASK 게시, fake echo CLI 실행 후 ACK/REPORT/영수/반영/processed를 재조회한다. 고유 자원 ID를 증거에 보관하고 생성한 세션은 revoke한다. 서비스에는 저장소 삭제 API가 없어 시험 이슈는 종료 절차 후 이력으로 남는다.
5. 호스트 process 시험: fake 자식이 자손을 만든 뒤 HOLD→검증한 PID+creationTime 트리 종료·잔류0 확인. shim 특수문자/한글 argv, Claude 사전 Bash allow가 있어도 built-in 도구 목록에서 셸 제거 확인.
6. 실제 codex exec/muse exec와 Codex/Claude 앱 수용은 docs/bridge.md §11.2에 따라 오케스트레이터가 수행한다.
7. s2 인증 회귀: runner emit 뒤 `node --test --test-isolation=none apps/cli/tests/tools/runner-live-session.test.mjs`. 발급 응답 배열과 flat/wrapped auth/me를 주입해 실제 HostRunner 생성·identity 일치, 누락 세션/잘못된 principal/다른 writer 차단을 확인한다. 원본 flat 응답의 undefined alias 예외도 재현한다. 운영 PASS로 합산하지 않는다.
8. s3 ACK 경합: 먼저 구독을 확정하고 pending 지시를 추가한다. virtual ACK HTTP 응답 전에 queued frame을 통과시켜 실제 delivery로 병합한 뒤 응답을 해제한다. ASK/HANDOFF 모두 ACK1·spawn1·REPORT1, source NOTE 중복0·outbox key 승계. 기존 ACKED crash/외부 ACK는 blocked·spawn0을 유지한다.
9. missing bare/absolute executable과 디렉터리를 실제 startChild 경로에 넣어 failed REPORT의 정확한 사유·not-applied·PID 없음을 확인한다. 일반/JSONL 단계 순서·single line·canary 마스킹·실제 evidenceRoot를 검사한다. live fixture 댓글을 같은 시각에 반복 생성해 nonce 중복0·COMPACT 형식 유지. 실기(c)(d)/bootstrap live는 호스트가 재실행한다.
10. s4 Windows PATH 회귀: 같은 디렉터리의 codex+codex.cmd에서 cmd 선택, exe 단독 선택, 빈 디렉터리/확장자 없는 파일만 존재하면 EXECUTABLE_NOT_FOUND. PATHEXT 빈 항목·기본 COM/EXE/BAT/CMD 순서·명시 순서·PATH 디렉터리 우선·명시 cmd·절대경로 보존을 검사한다. Codex argv는 서버 존재를 전제하는 mcp_servers.issus.enabled=false 대신 mcp_servers={}를 요구한다. 실제 Codex config/실행 수용은 호스트 재실기로 구분한다.

## Expected Results
R01–R11의 실행한 범위는 spawn·댓글·상태 수치로 판정. R12 실제 제품 sandbox·셸 거부는 fake/mock 결과로 PASS 처리하지 않는다. ACK 후 crash는 blocked 보존 또는 후처리 재개, 자동 재spawn 0. 상주 수신은 실행 중에도 제어를 처리한다.
