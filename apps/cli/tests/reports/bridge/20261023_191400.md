## Diagnosis and change
사용자 호스트 증거: `executables.codex="codex"`가 같은 npm 디렉터리의 확장자 없는 sh shim을 선택해 spawn ENOENT가 발생했다(`.cache/bridge-demo/runner-evidence/exp-codex-3.log`, failed REPORT1000076). 이 호스트 실기는 사용자 인계 관측이며 이번 세션에서 재실행하지 않았다.

`resolveExecutable`은 Windows의 확장자 없는 실행 이름을 PATH 디렉터리별 PATHEXT 순서로 조회한다. 확장자 없는 후보와 PATHEXT의 빈 항목을 제외한다. PATHEXT가 없으면 `.COM;.EXE;.BAT;.CMD;.PS1` 순서를 사용한다. 명시한 `.cmd` 이름·절대경로(확장자 없는 절대경로 포함)는 기존 선택을 유지한다. POSIX의 확장자 없는 PATH 조회도 유지한다. 파일이 없으면 기존 `EXECUTABLE_NOT_FOUND: <file>` 오류다.

추가 ASK6362528841: 호스트 Codex가 `mcp_servers.issus.enabled=false`로 인해 서버 command/url 없는 config를 만들고 exit1로 종료했다는 인계를 수신·ACK6362551932했다. adapter를 요청한 `-c mcp_servers={}`로 변경하고 기대 argv를 갱신했다. 실제 Codex 설정 병합·MCP 차단·모델 실행은 호스트 재검증 대상이며 argv 시험으로 수용을 주장하지 않는다.

`apps/cli/docs/usage.md` runner 기본값 표에 codex·claude npm shim의 PATHEXT 의존 또는 `.cmd` 절대경로 지정을 명시했다. Muse의 기존 기본 절대경로도 정확히 기록했다.
